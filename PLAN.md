# План: личный сборник аккордов (офлайн)

Личный каталог песен с текстом и аккордами над словами, транспонированием и офлайн-доступом на ПК и телефоне (PWA).

**Стек:** TypeScript · Vite · React · статические файлы песен · `vite-plugin-pwa`

**Принцип работы с планом:** пункты декомпозируем в чате; детали и решения дописываем сюда по мере необходимости.

| Элемент | Синтаксис | Пример из эталона |
|---------|-----------|-------------------|
| Мета | `{key: value}` | `{title: …}`, `{artist: …}`, `{key: G}` |

Подмножество ChordPro: без `{start_of_verse}` и прочего «полного» стандарта — только то, что нужно для просмотра и транспонирования.

**Требования к парсеру (из эталона, этап 2)**

- Обычные: `G`, `Am`, `Bm`, `D`, `F`, `C`, `A`, `Em`
- Слэш: `G/F#`, `F#`
- Добавки: `Cadd9`
- Альтерации: `Bb`, `F#`
- Строки без аккордов («I will price it»)
- Ремарки: `(verse chords)`

**Загрузка (предложение этапа 1)**

- `import.meta.glob('../songs/*.chordpro', { query: '?raw', eager: true })` (или аналог) — список и тело песни на этапе сборки.
- id файла = имя без расширения (`life-is-real`).
- Папка `songs/raw/` в бандл не попадает (только `.chordpro` из `songs/`).

#### 2. Декомпозиция (предложение)

**Цель этапа:** из `.chordpro` получить структуру для UI и уметь сдвигать все аккорды на ±N полутонов. Вёрстку «как UG» и кнопки +/− делаем в этапе 3, но API парсера сразу под неё.

**Модули**

| Файл | Ответственность |
|------|-----------------|
| `src/lib/chords.ts` | разбор/сборка одного аккорда, транспонирование |
| `src/lib/chordproParse.ts` | разбор всего файла → AST |
| `src/lib/chordproMeta.ts` | уже есть; при желании дергать из парсера |
| `*.test.ts` | эталонные кейсы из Queen |

**Модель аккорда (из эталона)**

```
root: A|B|C|D|E|F|G
accidental: '' | '#' | 'b'
quality: хвост до слэша — '', 'm', 'add9', 'maj7', … (как строка, не enum всех видов)
bass?: отдельная нота после `/` (G/F# → root G, bass F#)
```

Примеры: `G`, `Am`, `G/F#`, `Cadd9`, `F#`, `Bb`.

**Транспонирование**

- Хроматика: `C C# D D# E F F# G G# A A# B` (по умолчанию диезы).
- Сдвиг root и bass на N (−11…+11); `quality` не трогаем (`m`, `add9` остаются).
- Предпочтение бемолей: пока простое правило — если в исходном аккорде был `b`, писать бемоли; иначе диезы. (Усложнять «по тональности» не в этапе 2.)
- Нераспознанное в `[...]` (редкий мусор) — оставлять как текст, не ломать строку.

**AST файла**

```
SongAst {
  meta: { title, artist, key? }
  blocks: Block[]   // идут по порядку
}

Block =
  | { type: 'section', name: string }      // из {comment: Verse 1}
  | { type: 'line', parts: InlinePart[] }
  | { type: 'empty' }

InlinePart =
  | { type: 'chord', chord: Chord }        // исходный аккорд; транспонирование — отдельной функцией
  | { type: 'text', text: string }
```

Строка `[G]Guilt stains [G/F#]on my` →  
`chord G` + `text "Guilt stains "` + `chord G/F#` + `text "on my"`.

Хвостовые аккорды без текста (`[C] [F] [C]`) — parts только из chord (текст пустой/пробел).

**Правила разбора строк**

1. `{title|artist|key: …}` → meta (как сейчас).
2. `{# … }` → игнор.
3. `{comment: Name}` → section.
4. Пустая строка → empty.
5. Иначе — сканировать `[...]` и текст между ними.
6. Строка без скобок (`I will price it`, `(verse chords)`) → один text-part.

**API**

```ts
parseChordpro(source: string): SongAst
transposeChord(chord: Chord, steps: number): Chord
transposeSong(ast: SongAst, steps: number): SongAst  // глубокая копия с новыми аккордами
formatChord(chord: Chord): string                     // обратно в "G/F#"
```

**Тесты (минимум)**

1. Строка из Verse 1 Queen → нужная последовательность parts.
2. `{comment}` + meta на полном файле (или укороченном фрагменте).
3. `transposeChord`: `G`+2→`A`, `Am`+2→`Bm`, `G/F#`+2→`A/G#`, `Cadd9`+2→`Dadd9`, `Bb`+2→`C`.
4. `transposeSong` не меняет тексты и имена секций.

**Объём этапа 2 (готово, когда)**

- Парсер + транспонирование + тесты зелёные.
- Минимальный рендер на странице песни: **аккорды над текстом (как UG)** — без кнопок +/− (они в этапе 3).

**Справочник аккордов (решение по вопросу заказчика)**

- Транспонирование / парсер: **без** полного каталога — разбор `root + quality + /bass`, сдвиг нот.
- Диаграммы (палец/тап): **отдельный** справочник частых форм (`G`, `Am`, `Cadd9`…) — этап 5+, не блокирует 2–3.
- Не пытаемся заранее заготовить «все аккорды» (комбинаторика слэшей и надстроек бесконечна).

**Не делаем в этапе 2:** капо как отдельная логика, диаграммы, предпочтение тональности из `{key}`, UG→ChordPro конвертер.

**Стек**

| Что | Выбор |

`react-chords` на npm сейчас не надёжен (404); чужой React-компонент не обязателен — схема рисуется просто.

**Маппинг наших аккордов → база**

- `G` → key `G`, suffix `major`
- `Am` → key `A`, suffix `minor`
- `Cadd9` → key `C`, suffix `add9`
- `F#` → key `F#`, suffix `major`
- `Bb` → key `Bb`, suffix `major`
- `G/F#` → суффикс `/F#` в chords-db (без подмены обычным G); нет формы → «не найдена», не упрощаем

Несколько `positions` в базе → берём **первые две**; на карточке мини-стрелки ‹ › и метка `1/2`.

**MVP — сделано**

1. Зависимость `chords-db`, `chordDiagramLookup.ts` + тесты.
2. `ChordDiagram` (SVG) + `ChordPopover` (backdrop / Escape / ×).
3. В `SongView` аккорд — кнопка.
4. Покрытие эталона Queen, включая `G/F#` (схема G).
5. Нет формы → «Схема не найдена».

**Не в MVP:** все инструменты кроме гитары, ховер-only, анимация как на UG, правильные слэш-формы, code-split базы.

## Контент и перенос с UG

Источник сейчас: личный список на [Ultimate Guitar My Tabs](https://www.ultimate-guitar.com/user/mytabs) (~≤100 песен).

**Стратегия:** ручной перенос в файлы проекта (не скрейпер).

1. Сделать приложение полезным на 1–3 песнях (формат + просмотр + транспонирование).
2. Дать шаблон `.chordpro` и короткий чеклист «как скопировать с UG».
3. Переносить песни по мере игры (не обязательно все 100 сразу).
4. Репозиторий = бэкап и источник правды; UG остаётся справочником при переносе.

Формат вставки с UG: текст с аккордами над строками → при переносе превращаем в ChordPro (`[Am]слово`). На этапе 1–2 можно добавить простой хелпер «вставил UG-текст → получил ChordPro» *локально в приложении/скрипте*, без обращения к сайту UG.
